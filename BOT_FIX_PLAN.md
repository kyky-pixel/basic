# Диагноз по вашему логу (почему TP/SL только у части позиций)

По вашему фрагменту лога причина подтверждена явно:

1. После BUY TP часто падает с `ErrCode 170131: Insufficient balance`.
2. Для DOGE и TP, и SL падают с `ErrCode 170137: Order quantity has too many decimals`.
3. На старте есть позиции без ордеров (`ETHUSDT: ордеров нет`), и бот их не «долечивает».

Итог: покупка проходит, а защита частично не ставится. Затем бот продолжает открывать новые позиции, и «голые» позиции накапливаются.

---

## Важный момент про цену TP/SL для «старых» позиций

Да, вы правы: для восстановления нужно **помнить цену входа**. Если на аккаунте есть монета, но нет истории покупки, бот не сможет корректно посчитать TP/SL от entry.

Поэтому нужно хранить ledger покупок (например `entry_ledger.json`), где для каждой пары сохраняется entry price:

```json
{
  "LINKUSDT": { "entry_price": 9.173, "ts": "2026-04-14T17:46:11" },
  "UNIUSDT":  { "entry_price": 3.186, "ts": "2026-04-14T17:46:15" }
}
```

Приоритет источников для восстановления:
1. `entry_ledger.json`
2. `bot.log` (если есть строки BUY)
3. иначе — пропуск позиции до ручной цены

---

## Что исправить в `bot.py` обязательно

### 1) Ставить TP/SL от фактического остатка монеты, а не от `MAX_TRADE_USD / price`

После BUY сделайте чтение баланса монеты и используйте его с запасом под комиссию (`*0.997`).

### 2) Убрать hardcoded precision для qty/price

Вместо `SYMBOL_PRECISION` берите `qtyStep`, `minOrderQty`, `tickSize` через:
- `get_instruments_info(category="spot", symbol=symbol)`

и округляйте **вниз к step**.

### 3) На старте и в каждом цикле «долечивать» позиции без TP/SL

Если позиция есть, а `tp_order_id`/`sl_order_id` отсутствуют — немедленно пробовать поставить недостающий ордер.

### 4) Добавить retry на постановку ордеров

2–3 попытки с паузой 0.5–1.0 сек для временных ошибок API.

### 5) Включить лимит позиций при BUY

Сейчас `MAX_POSITIONS` объявлен, но фактически не ограничивает новые входы.

### 6) Сохранять entry price в ledger при каждом BUY

Сразу после подтверждённой покупки записывать entry в файл/БД, чтобы после рестарта восстановление TP/SL работало без log-парсинга.

---

## Скрипт восстановления из лога + ledger

`recover_missing_tp_sl.py` теперь:
- читает entry price из `entry_ledger.json`;
- если в ledger нет — берёт из `bot.log`;
- если нет ни там, ни там — пропускает позицию (и пишет причину);
- берёт реальные правила символа (`qtyStep`, `tickSize`, `minOrderQty`) с биржи;
- округляет qty/price по правилам биржи;
- проверяет, какие TP/SL уже есть;
- ставит только недостающие ордера (`--execute`), по умолчанию dry-run;
- использует retry на постановку ордеров.

Перед запуском восстановления можно собрать ledger напрямую из лога:

```bash
python build_entry_ledger.py --log bot.log --out entry_ledger.json
python build_entry_ledger.py --log bot.log --out entry_ledger.json --merge
```

### Запуск

```bash
python recover_missing_tp_sl.py --log bot.log --ledger entry_ledger.json
python recover_missing_tp_sl.py --log bot.log --ledger entry_ledger.json --execute
```
